## Project Overview

Tactical Scout is an AI-powered football (soccer) player analysis tool that finds statistically similar players ("tactical clones") using a PyTorch autoencoder for embeddings and a LangGraph ReAct agent for conversational queries.

## Commands

### Setup
```bash
pip install -r requirements.txt
```

### Train the autoencoder (must run before starting backend)
```bash
python backend/autoencoder.py
```
Outputs `backend/artifacts/embeddings.pt` and `backend/artifacts/player_info.pkl`.

### Run the backend
```bash
uvicorn backend.main:app --reload
```
Server runs on `http://localhost:8000`.

### Run the frontend
Open `frontend/index.html` directly in a browser, or serve it:
```bash
python -m http.server 3000 -d frontend
```

## Architecture

### Data Flow
1. User sends a message via `frontend/script.js` → `POST /chat` on the FastAPI backend
2. `backend/main.py` passes the message as a `HumanMessage` to the LangGraph agent in `backend/agent.py`
3. The ReAct agent (Groq llama-3.3-70b-versatile) decides whether to call the `get_similar_players` tool
4. The tool loads pre-computed embeddings from `backend/artifacts/` and returns top-5 players by cosine similarity
5. The LLM generates a natural-language response returned to the frontend

### ML Pipeline (`backend/autoencoder.py`)
- Reads `data/players_data-2024_2025.csv` (~200+ FBRef columns)
- Filters: excludes GKs, requires 500+ minutes played
- Normalizes Goals and Assists to per-90 metrics
- Preprocessing: `PowerTransformer` (Yeo-Johnson) → `RobustScaler`
- Autoencoder architecture: `num_features → 32 → 16 → 8 → 16 → 32 → num_features` (latent dim = 8)
- Trains for 100 epochs, batch size 32, Adam lr=0.001, MSE loss
- Saves embeddings tensor and player metadata via `joblib`

### Agent (`backend/agent.py`)
- LLM: Groq API (`llama-3.3-70b-versatile`), loaded from `backend/.env`
- Single tool: `get_similar_players(player_name: str)` — cosine similarity over pre-computed embeddings
- Artifacts are loaded once at module initialization (lazy loading, not per-request)

### Frontend (`frontend/`)
- Vanilla HTML/CSS/JS, no framework
- Calls `localhost:8000/chat`, renders responses in a scrollable chat window

## Environment

Create `backend/.env` with:
```
GROQ_API_KEY="..."
GOOGLE_API_KEY="..."   # imported but currently unused
```

## Key Constraints

- Artifacts (`embeddings.pt`, `player_info.pkl`) must be generated by running `autoencoder.py` before the backend can serve requests — the agent raises `FileNotFoundError` otherwise.
- The autoencoder uses CUDA if available, falls back to CPU.
- There are no tests, no linter config, and no CI/CD pipeline.
